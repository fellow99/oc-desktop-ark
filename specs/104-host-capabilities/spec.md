> 模块：`104-host-capabilities`｜文档：spec.md（做什么 + 验收判据）
> 上位依据：`docs/000-工程规划.md` §6（#8/#9/#10/#15）、§8.4、§10、§11（P0-I/P0-J）、§14.2
> 运行时契约：`@fellow99/node-bridge` 库文档（[fellow99/ohos-node-bridge](https://github.com/fellow99/ohos-node-bridge)）§5.3、§5.4、§6.1

## 1 模块概述

### 1.1 目的

给运行在本机的服务端一组**受控的宿主能力**：查询并归因权限、跳转应用设置、选择目录与文件、打开外链、发通知、读取运行事实。
能力清单是**冻结契约**：名字、入参、出参、失败语义都固定；调用方与被调用方各写一遍就等于两套契约（C1）。

### 1.2 要解决的问题

| # | 问题 | 不解决的后果 |
|---|---|---|
| Q1 | 服务端进程没有平台 API，做不了「弹选择器 / 查权限 / 跳设置」 | 用户无法选工作区，只能手打路径或放弃 |
| Q2 | 能力未注册时如果返回空值 | 调用方解引用空值 → 整个应用崩溃（旧壳事故） |
| Q3 | 目录选择返回的是资源标识而不是文件路径 | 服务端拿它当路径 `stat`，得到「文件不存在」的假象 |
| Q4 | 权限查询存在已知假阴性 | 用户明明授权了，界面却说「没权限」 |

### 1.3 范围

- **在**：七项能力的实现与失败语义、注册面完整性、目录选择与授权（含每次启动重新激活）、权限归因、外链协议白名单、通知发布、运行事实快照、能力自检入口。
- **不在**：窗口与渲染（→ 103）、启动编排与状态机（→ 101）、口令与鉴权（→ 105）、权限声明面本身（→ 107）、Git 插件业务（→ 108）。

## 2 用户故事

| # | 故事 | 关联需求 |
|---|---|---|
| US-1 | 作为用户，我能用系统目录选择器指定工作区，且代理真的能读写它 | FR-104-007、010、011 |
| US-2 | 作为用户，权限被拒时我能看到「这个权限是干什么的、现在该点哪里」 | FR-104-005、006 |
| US-3 | 作为用户，点开外链不会把应用变成浏览器，也不会被奇怪协议劫持 | FR-104-012 |
| US-4 | 作为用户，长任务结束时的提醒能发出来；发不出来时我知道是总开关没开 | FR-104-013 |
| US-5 | 作为诊断者，我一次调用就能读到运行状态、版本与平台能力标志 | FR-104-014 |

## 3 功能需求

> 关键词：MUST / SHOULD / MAY 按 RFC 2119 解释。

**FR-104-001（冻结能力清单）**：v1 能力名 MUST 恰为七项：`runtime.facts`、`perm.check`、`perm.openAppInfo`、`fs.pickFolder`、`fs.pickFiles`、`shell.openExternal`、`notify.show`；MUST NOT 增加、改名或合并；改名 MUST 视为破坏性变更（版本策略另行登记）。

**FR-104-002（结构化结果）**：每次调用 MUST 返回可解析的结构化结果，成功 MUST 含能力名与结果字段；失败 MUST 含错误码、人读说明与下一步建议（若有）。MUST NOT 只返回布尔或空串。

**FR-104-003（未注册即拒绝）**：未注册的能力名 MUST 被明确拒绝（错误码可判定），MUST NOT 返回空值、默认值或「成功但无数据」，MUST NOT 使调用方或宿主崩溃。

**FR-104-004（参数校验）**：必需参数缺失或非法 MUST 返回参数错误，MUST NOT 用缺省值猜测调用意图；解析失败 MUST NOT 把异常抛给传输层。

**FR-104-005（权限查询）**：`perm.check` MUST 返回：是否已授予、该权限的用途归因、未授予时的下一步动作；MUST 附带「已知假阴性」提示（已授予仍可能报未授予，判断可用性应看真实读写结果）。

**FR-104-006（去应用设置）**：`perm.openAppInfo` MUST 打开本应用的系统设置页；无法打开时 MUST 返回错误码与人读说明（含手动路径提示），MUST NOT 静默失败。

**FR-104-007（目录选择）**：`fs.pickFolder` MUST 单选一个目录，并返回**服务端可直接使用的文件系统路径**；若平台只给出资源标识且无法转换，MUST 如实返回标识并标注「不可直接当路径用」，MUST NOT 伪造路径。

**FR-104-008（文件选择）**：`fs.pickFiles` MUST 支持多选（单次上限 SHOULD 为 32），返回条目 MUST 与目录选择同构（路径 + 标识 + 可用性）。

**FR-104-009（取消语义）**：用户取消或未选择任何项 MUST 返回专门的「已取消」结果，MUST 与失败区分；调用方 MUST 能据此判断「不要重试」。

**FR-104-010（选择后授权）**：选择成功后 MUST 立即为所选条目申请可持久化的读写授权；申请失败 MUST NOT 推翻本次可用性，但 MUST 如实返回「未持久化」与原因。

**FR-104-011（每次启动重新授权）**：已记录的目录 MUST 在**每次应用启动**时重新申请授权（平台语义）；MUST NOT 把上一次的授权结果或选择器标识当作跨启动凭据；重新授权失败 MUST 可见（能力结果 + 诊断），MUST NOT 声称仍然可写。

**FR-104-012（外链白名单）**：`shell.openExternal` MUST 只放行 `http`/`https`，其它协议 MUST 拒绝并记录；交给系统解析失败 MUST 记为可见错误，MUST NOT 在应用内打开任意网页。

**FR-104-013（通知）**：`notify.show` MUST 要求非空正文，缺正文 MUST 拒绝；发布失败 MUST 回传系统错误码与「去系统设置打开通知」之类的下一步，MUST NOT 假装已送达。

**FR-104-014（运行事实）**：`runtime.facts` MUST 返回：运行状态与阶段、运行时版本、进程号、日志位置与条数、最近错误、能力标志（至少含终端/PTY 的「不支持 + 原因 + 证据」）。能力标志 MUST 是标志而非异常。

**FR-104-015（不阻塞启动）**：能力注册 MUST 在启动投递之前完成；能力的用户交互（选择器、授权、通知）MUST NOT 阻塞启动编排或首屏渲染；单次调用超时 SHOULD 可配置，长操作 MUST 允许远大于默认值的超时。

**FR-104-016（失败留痕）**：每次失败 MUST 留下一条可检索日志（能力名 + 错误码 + 原因），并 MUST 能在诊断面板/日志尾中看到；MUST NOT 出现「界面无反应且日志无线索」。

**FR-104-017（自检默认关闭）**：能力自检清单 MUST 默认空；出厂/发布构建 MUST NOT 自动弹窗、发通知或打开选择器；验证时临时填项 MUST 只影响本次构建。

**FR-104-018（不注册空实现）**：尚未实现的能力名 MUST 以「未实现」结果注册或直接不注册，MUST NOT 注册一个什么都不做的空实现；新增能力 MUST 先登记名字与失败语义。

## 4 关键实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `CapabilityName`（能力名） | 名称、是否异步、是否用户交互 | 名单冻结；改名=破坏性变更 |
| `CapabilityRequest`（能力请求） | 能力名、参数对象、调用时刻 | 参数来自外部输入，解析失败不得抛 |
| `CapabilityResult`（能力结果） | 成功标志、能力名、错误码、说明、下一步 | 失败必须可判定；不得为空 |
| `DirectoryGrant`（目录授权） | 根标识、真实路径、资源标识、读写模式、是否持久化、激活时刻、最近错误 | 每次启动重新激活；路径与标识一一对应 |
| `CapabilityFlag`（能力标志） | 能力名、是否支持、原因、证据、后续计划 | 不支持必须是标志，不得以异常表达 |
| `ProbeItem`（自检项） | 能力名、参数串 | 默认空；出厂不执行 |

## 5 验收场景

**AS-104-01 七项能力逐项可调用**（FR-104-001/002）
- Given 应用已启动、能力已注册；When 依次调用七项能力（含合法最小参数）；Then 每项 MUST 返回结构化结果，成功项含能力名、失败项含错误码与说明，MUST NOT 有未捕获异常或崩溃

**AS-104-02 未注册能力不崩**（FR-104-003/018）
- Given 调用一个不在名单里的能力名
- When 派发该调用
- Then MUST 得到「未注册」类错误；应用 MUST 继续运行；MUST NOT 返回空值或成功

**AS-104-03 目录选择三种结局**（FR-104-007/008/009）
- Given 用户打开目录选择器；When ① 选可访问目录 ② 直接取消 ③ 选到无法转换为路径的条目；Then ① 返回可用路径 ② 返回「已取消」 ③ 返回标识 + 「不可直接当路径用」；三者 MUST 可区分

**AS-104-04 重启后授权需重申**（FR-104-011）
- Given 上一次运行已选目录并成功授权
- When 杀掉进程重启，直接让服务端读写该目录
- Then 若重放授权失败：MUST 返回可读拒绝原因，且 MUST NOT 声称可写；诊断 MUST 记录「本次重新激活失败」

**AS-104-05 假阴性可见**（FR-104-005）
- Given 用户已在系统设置授予某权限；When 调用权限查询而平台返回「未授予」；Then 结果 MUST 同时含「未授予」与「已知假阴性」提示并给出下一步，MUST NOT 只有一句「没权限」

**AS-104-06 外链协议**（FR-104-012）
- Given 请求打开 `https://…`、`http://…`、`file://…`、`javascript:…`
- When 逐项调用
- Then 前两者 MUST 交给系统；后两者 MUST 拒绝并留日志；应用 MUST NOT 自身导航

**AS-104-07 通知失败可见**（FR-104-013）
- Given 系统通知总开关关闭
- When 调用通知
- Then MUST 返回系统错误码与下一步说明；MUST NOT 返回成功

**AS-104-08 运行事实与能力标志**（FR-104-014）
- Given 运行时处于运行或失败态
- When 调用运行事实
- Then 返回 MUST 含状态、阶段、版本、进程号、日志条数与终端能力标志；终端标志 MUST 为「不支持 + 原因 + 证据」

## 6 非功能需求

| 类别 | 要求 |
|---|---|
| 时延 | 非交互能力 SHOULD 在 100 ms 量级返回；交互能力（选择器/授权/通知）MUST 允许分钟级超时且不得被默认超时误杀 |
| 可靠性 | 重复调用 MUST 幂等（除通知会重复发送外，查询类结果一致）；任何失败 MUST NOT 让应用退出 |
| 安全 | 能力 MUST NOT 回传文件内容（只回传路径/标识）；外链 MUST 白名单；MUST NOT 新增权限声明（声明面=使用面） |
| 可观测 | 每项能力的调用与失败 MUST 各有一条日志；结果 MUST 可在诊断面板复现 |
| 可测试 | 参数解析、结果拼装、协议白名单 MUST 是纯函数可离线单测；真机判据 MUST 可用日志 + 返回 JSON 断言 |
| 兼容 | 目标设备仅 2in1 / tablet；用户目录按平台授权语义降级，不允许假设可写 |

## 7 假设与约束

- 能力调用方只在**同一应用进程**内（本机服务端），不面向局域网或外部调用者；能力不是远程 API。
- 目录选择、授权、通知都是**用户可见动作**，可能长时间不返回或被用户拒绝（这不是缺陷）。
- 平台约束：选择器授予的是临时授权，**每次启动需重新激活**（规划 §8.4）；授权必须传真实路径。
- 权限查询存在已知假阴性（旧壳结论，规划 §6 #9）；「查不到」不等于「不能用」。
- 通知在 v1 不作为业务路径（规划 §6 #15）；能力存在只为插件/诊断与后续阶段。
- `perm.request`、`log.hilog` 等名字不在 v1 冻结名单；对它们的调用 MUST 落为「未注册」（FR-104-003）。
