## 1 模块概述

### 1.1 目的

把「上游源码」稳定地变成「可投放、可校验、可回滚的载荷」：
**幂等打补丁（带基线守卫）→ 安装全平台依赖 → 按目标运行时构建单文件产物 → 裁剪设备不可用件 → 组装投放 → 生成哈希清单 → host 门禁**。

### 1.2 要解决的问题

| # | 问题 | 不解决的后果 |
|---|---|---|
| Q1 | 上游仓库被两个工程共用，工作树可能带着另一个工程的补丁 | 把别人的改动当「本工程已打补丁」，产物来源不可复现 |
| Q2 | 上游构建默认为更新的运行时版本构建 | 产物语法/内建模块与设备运行时错位，运行期才炸 |
| Q3 | 产物含多平台原生件与设备不可用的二进制 | 体积虚高，且可能被错误加载 |
| Q4 | 载荷是数万小文件时无法直接进包 | 打包卡死或首启崩溃 |
| Q5 | 产物的完整性没有任何记录 | 无法判断「装上去的东西」与「验过的东西」是否同一份 |

### 1.3 范围

- **在**：补丁集与幂等判据、基线/工作树守卫、依赖安装、构建参数、裁剪规则、投放形态与回退、哈希清单、host 门禁、产物统计。
- **不在**：运行时二进制投放（→ 101）、渲染与加载页（→ 103）、补丁内容本身的设计（→ 106）、应用侧权限（→ 107）。

## 2 用户故事

| # | 故事 | 关联需求 |
|---|---|---|
| US-1 | 作为构建者，我在打补丁前就被拦住，而不是在「补丁应用失败」的半路 | FR-102-002 |
| US-2 | 作为构建者，我重复执行同一条流水线得到同一份产物（哈希可比） | FR-102-001、FR-102-007 |
| US-3 | 作为构建者，我能在没有设备的情况下确认「产物能在同版本运行时上起服务」 | FR-102-008 |
| US-4 | 作为排障者，我能从清单看出每个载荷文件的大小与哈希 | FR-102-007 |
| US-5 | 作为用户，我不会因为载荷缺失/被裁剪过度而看到「服务起不来」却无解释 | FR-102-009 |

## 3 功能需求

> 关键词：MUST / SHOULD / MAY 按 RFC 2119 解释。

**FR-102-001（幂等补丁）**：补丁应用 MUST 幂等：以「反向校验通过」判定已应用并跳过；每次应用后 MUST 再做一次反向校验，不通过 MUST 失败（不留半应用状态）；补丁 MUST NOT 使用三方合并强行落地。

**FR-102-002（基线守卫）**：补丁流程 MUST 在改动任何文件之前校验两项：① 上游提交号等于锁定基线（可用环境变量覆盖）；② 工作树干净（状态输出为空）。任一不满足 MUST 以退出码 2 拒绝执行，并 MUST 打印可执行的处置建议（含「显式丢弃」的命令）；只有显式「重置 + 确认」双参数才允许丢弃本地改动，且 MUST 先打印将要删除的未跟踪项。

**FR-102-003（构建参数对齐）**：产物构建 MUST 指定与设备运行时一致的语言目标（24），MUST 指定产物目标平台（arm64/linux 形态仅用于产物收集），MUST 只产单文件 bundle、不产独立可执行镜像；任一参数缺失 MUST 视为构建失败。

**FR-102-004（依赖覆盖）**：依赖安装 MUST 覆盖所有平台/架构的可选依赖（不按当前宿主平台过滤），否则打包器会在收集阶段报缺件。

**FR-102-005（裁剪）**：裁剪 MUST 只删除「非目标架构」与「平台不可用」的原生件（含持久终端助手可执行文件），MUST 保留纯 JS/wasm 资源；每条裁剪规则 MUST 可在清单与门禁里被验证（被裁条目消失、必需条目仍在）。

**FR-102-006（投放形态）**：投放 MUST 首选「包内只读目录 + 运行时直读」（零解压、零首启等待）；仅当直读不可行时改用「单归档 + 运行时自解包」。归档解包器 MUST 在运行时侧（宪法 C3），宿主侧 MUST NOT 解压业务载荷；解包 MUST 拒绝越出目标目录的条目，MUST 跳过并计数不支持的链接条目（不静默）。

**FR-102-007（哈希清单）**：流水线 MUST 生成清单，至少含：schema 版本、上游提交号、产物形态、每个文件的相对路径/字节数/SHA-256、总文件数与总字节数；重复构建同一输入 MUST 得到相同清单（哈希集合一致）。清单 MUST 入库（只含哈希，不含二进制）。

**FR-102-008（host 门禁）**：流水线 MUST 在投放后执行 host 门禁：版本/帮助自检、服务启动、健康端点 200、根路径返回真实界面（非 404/空页）、事件流首个事件可读；任一项失败 MUST 阻断（非零退出），MUST NOT 把未过门禁的产物推给设备。门禁 MUST 打印所用运行时版本，版本与设备不一致时 MUST 标注为「非等价证据」。

**FR-102-009（可证伪残留）**：门禁 MUST 断言「必需条目存在」与「应裁条目不存在」两类事实；断言集合 MUST 由清单驱动，MUST NOT 靠人工目检。

**FR-102-010（体积与条目统计）**：流水线 SHOULD 输出条目数与体积统计，并与预算对比；超出预算 SHOULD 告警但不阻断（预算由规划 §7.2 维护）。

**FR-102-011（不改上游脚本）**：流水线 MUST NOT 向上游仓库新增构建脚本或改变其构建语义；一切差异 MUST 落在本工程脚本与幂等补丁里。

**FR-102-012（失败即停）**：任一阶段失败 MUST 立即非零退出并保留现场（不自动回滚已解压产物、不自动重试）；日志 MUST 标明失败阶段。

## 4 关键实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `PatchSet`（补丁集） | 目录版本号、条目列表、每条必要性、SHA-256 | 与基线一一对应；换基线必须新建目录 |
| `BaselineGuard`（基线守卫） | 期望提交号、实际提交号、工作树状态、重置开关 | 守卫不通过则不进入任何写操作 |
| `BuildArtifact`（构建产物） | 入口单文件、资源目录、内嵌界面归档 | 入口与内嵌界面归档必须同时存在 |
| `PruneRule`（裁剪规则） | 匹配模式（包 id 粒度）、理由 | 规则可枚举、可断言 |
| `Payload`（载荷） | 形态（直读 / 归档）、根路径、条目数、总字节 | 形态由「是否可写」决定，不编译期开关 |
| `PayloadManifest`（载荷清单） | schema、基线、形态、files[]、totals | 只含哈希；与载荷逐字节对应 |
| `DropTarget`（投放目标） | 只读资源目录、可写沙箱目录 | 业务文件只落这两处 |
| `GateReport`（门禁报告） | 检查项、期望、实测、结论、运行时版本 | 全绿才算通过 |

## 5 验收场景

**AS-102-01 脏工作树被拒**（FR-102-002）
- Given 上游工作树存在未提交改动
- When 执行补丁流程（不带重置参数）
- Then MUST 以退出码 2 结束，MUST 打印前若干条脏文件与处置命令，且上游文件 MUST NOT 被改动

**AS-102-02 基线不符被拒**（FR-102-002）
- Given 上游提交号不等于锁定基线
- When 执行补丁流程
- Then MUST 以退出码 2 结束并提示「换基线须新建补丁目录」

**AS-102-03 幂等重放**（FR-102-001）
- Given 补丁已应用
- When 再次执行补丁流程
- Then MUST 全部判为「已应用，跳过」，退出码 0，上游文件 SHA-256 不变

**AS-102-04 目标对齐**（FR-102-003）
- Given 未设置语言目标变量
- When 执行构建
- Then 产物 MUST 被门禁或构建脚本判为不合格（不得静默按默认目标产出）

**AS-102-05 裁剪可证伪**（FR-102-005/009）
- Given 产物含非目标架构原生件与终端助手可执行文件
- When 执行裁剪与门禁
- Then 清单中这些条目 MUST 缺席，必需条目（入口、内嵌界面归档）MUST 在场；缺任一项 MUST 失败

**AS-102-06 直读优先**（FR-102-006）
- Given 包内只读目录中的载荷可被运行时直接加载
- When 投放与启动
- Then 首启 MUST NOT 产生解压等待；清单 MUST 记录形态为「直读」

**AS-102-07 归档回退幂等**（FR-102-006/007）
- Given 采用归档回退形态
- When 用同一归档连续启动两次
- Then 第二次 MUST 跳过解包（以归档哈希比对判定，不以文件存在性判定）

**AS-102-08 门禁阻断**（FR-102-008）
- Given 根路径返回 404（内嵌界面归档缺失）
- When 执行 host 门禁
- Then MUST 非零退出并打印响应码；流水线 MUST NOT 继续到「允许上机」

**AS-102-09 清单可复现**（FR-102-007）
- Given 同一上游提交、同一构建参数
- When 连续构建两次
- Then 两次清单的 `files[].sha256` 集合 MUST 相同

## 6 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 增量场景 MUST 复用已安装依赖与已暂存产物；单次全量流水线 SHOULD 在常规构建机上 ≤ 30 min（⬜ 实测记录） |
| 可复现 | 输入（基线 + 补丁集 + 构建参数 + 依赖锁）相同 ⇒ 清单哈希集合相同；工具链版本 MUST 记录在清单头 |
| 体积 | 载荷 MUST 落在规划 §7.2 预算内；每条裁剪 MUST 有理由（不因「看着没用」而删） |
| 安全 | 流水线 MUST NOT 把口令、签名材料、密钥写入产物或清单；清单只含哈希 |
| 可观测 | 每阶段一行「阶段 + 结果 + 计数」，失败带原因；产物统计可读 |
| 可移植 | 流水线 MUST 在 Windows（Git-Bash）与 Linux 构建机上行为一致；路径分隔符差异 MUST 由脚本吸收 |

## 7 假设与约束

- 上游基线固定（tag/提交号），补丁按该基线生成；升级基线属于新任务。
- 上游依赖安装需要联网；离线环境 MUST 先预热缓存（⬜ 缓存目录与内容待定稿）。
- 裁剪只处理「已知的设备不可用件」；未知原生件 MUST 通过门禁/清单暴露，而不是默认保留。
- 直读形态是否可行取决于平台对包内只读目录的读取约束（⬜ P0-G 裁决）；不可行即走归档回退。
- 设备侧真实运行能力不能由 host 门禁证明（仅证明「同版本运行时能跑」）。
