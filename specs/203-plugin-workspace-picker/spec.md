## 1. 概述

「打开项目 / 选择工作区目录」对话框当前只能从沙箱（`HOME` 被宿主改写后的 `filesDir`）出发浏览，用户**无法**把「文档」「下载」里的目录选为工作区。本模块给该对话框补上三个主目录入口（**沙箱 / 文档 / 下载**），并把「目录枚举」「目录权限」两件只有服务端进程/ArkTS 侧才具备的能力，经**壳专用 opencode 插件**暴露给渲染层。

### 1.1 两个半边与边界

| 半 | 内容 | 落点 |
|---|---|---|
| 能力半 | 三根路径解析、**带根围栏**的目录枚举、权限预检/申请、应用信息页深链、目录创建 | 壳专用 opencode 插件（服务端进程内） |
| 界面半 | 对话框顶部三个主目录 Tab；无权限时的「请求权限 / 刷新」两按钮；新建文件夹 | 上游 `packages/app` 的**幂等补丁** |

**范围包含**：三根 Tab、目录列举与逐级进入、权限门（两个按钮）、新建文件夹、根围栏、能力不可用时的完整回退、真机闭环验收。

**不包含**：
- **桌面**根（属 `system_basic` + 必须 ACL，本版已撤销该项申请，见 `docs/ACL配置.md` §1.2）；
- **主目录记忆**（需求未要求；每次打开停在「沙箱」）；
- 任意路径手动输入、隐藏文件开关、整盘浏览、文件选择、重命名/删除；
- 新增或变更任何权限声明（`module.json5` 不动）；
- ArkTS 侧业务改动（三根路径由插件在服务端解析，不依赖 `ContextPath` 类空实现）。

## 3. 功能需求

> 级别：MUST / MUST NOT / SHOULD（RFC 2119）。

### 3.1 主目录与切换

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-203-001 | 对话框顶部 MUST 渲染**三个**主目录 Tab，顺序固定为 `沙箱 / 文档 / 下载`；MUST NOT 出现「桌面」Tab | DOM（`[role="tab"]`）恰好 3 项且 `data-root-id` 依次为 `sandbox`/`documents`/`download` |
| FR-203-002 | 切换主目录 MUST 重置浏览视图（清空树、清空选中、清空错误）并重新列出该主目录根 | 真机：切换后树只含该根的直接子目录 |
| FR-203-003 | 首次打开对话框 MUST 默认停在「沙箱」；MUST NOT 记忆上次主目录 | 重开对话框仍为沙箱（无持久化键写入） |
| FR-203-004 | 沙箱根 MUST 为 `<沙箱家目录>/workspace`，解析时不存在则自动创建 | 删除该目录后重开 → 自动重建并正常列出 |
| FR-203-005 | 文档/下载根 MUST 为用户主目录下的 `Documents` / `Download`；不存在或非目录时 MUST 标记为不可用并给出原因，MUST NOT 静默换根 | 真机：人为改坏路径 → 该 Tab 显示不可用原因，其余 Tab 不受影响 |
| FR-203-006 | 三根解析结果 MUST 写入结构化日志（id / 绝对路径 / 可用性 / 时间戳） | hilog 有 `workspace-root` 三行 |

### 3.2 目录列举（复用壳侧能力）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-203-010 | 三个主目录模式下的目录列举 MUST 经壳侧插件能力完成（服务端做存在性、类型与根围栏判定），MUST NOT 在渲染层自实现文件系统遍历 | 列举失败时能拿到结构化错误码（`EACCES` / `not-found` / `out-of-root`） |
| FR-203-011 | 只渲染目录项（不含文件）；按名称排序；MUST 过滤以 `.` 开头的隐藏项；MUST NOT 提供「显示隐藏文件夹」开关 | DOM：无文件行、无 `.` 前缀行、无隐藏开关 |
| FR-203-012 | 浏览域 MUST 锁定在选定主目录内：展开、面包屑与「上级」MUST NOT 上溯到主目录根之上；越界导航 MUST 被忽略（不报错、不改变视图） | 真机：根层「上级」无效；无任何可提交任意绝对路径的输入框 |
| FR-203-013 | 三根模式下 MUST 移除手动路径输入（路径输入框与建议浮层） | DOM：根层无路径输入框 |
| FR-203-014 | 采纳前 MUST 再判一次根围栏；MUST 回传**绝对真实路径**并经既有 `onSelect` 链路创建/切换工作区 | 真机：选中子目录后工作区根 = 该绝对路径 |

### 3.3 权限门（本版与 hos 的差异）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-203-020 | 点「文档」「下载」Tab MUST NOT 主动发起权限请求 | 授权已撤销时点 Tab，无系统弹窗 |
| FR-203-021 | 有权限时 MUST 显示目录列表 | 真机：已授权 → 列表出现 |
| FR-203-022 | 无权限时 MUST NOT 显示列表，MUST 改为显示**两个**按钮：`请求权限`、`刷新`，并 MUST 显示可读原因文案 | DOM：无树节点、恰好 2 个按钮 |
| FR-203-023 | `请求权限` MUST 发起系统授权请求（按钮进入进行中态并禁用重复点击）；请求返回后 MUST 重新判定权限并据此渲染列表或两按钮 | 真机：同意后列表自动出现；拒绝后仍在两按钮态且有原因 |
| FR-203-024 | `刷新` MUST 重新判定权限与可读性并重渲染（列表或两按钮） | 真机：系统设置里打开开关后点刷新 → 列表出现 |
| FR-203-025 | 权限判定的**事实判据** MUST 是一次真实的目录枚举是否成功，MUST NOT 只依赖权限查询接口的返回值 | 授权开关已开但查询接口返回 false 时，仍以列举成功为准显示列表 |
| FR-203-026 | 权限桥不可用（无宿主桥 / 无信箱 / 抛错）时 MUST 明确归因（文案可读），MUST NOT 静默失败、MUST NOT 假装成功 | 真机：断开桥后点「请求权限」→ 出现归因文案 |
| FR-203-027 | 权限相关操作 MUST NOT 改变全局状态（不改权限声明面、不改插件树、不重启服务） | 变更文件清单无 `module.json5` |

## 4. 关键实体

| 实体 | 字段 | 说明 |
|---|---|---|
| 主目录（Root） | `id` ∈ {`sandbox`,`documents`,`download`}、`path`（绝对路径，不可用时为空串）、`available`、`needsPermission`、`reason` | 由插件解析；`reason` 供 UI 显示 |
| 目录项（Entry） | `name`、`type` ∈ {`directory`,`file`} | 只渲染 `directory`；按目录优先 + 名称排序 |
| 列举结果 | `ok`、`code`、`message`、`entries`、`count`、`total`、`truncated` | `code` 稳定字符串：`EACCES`/`EPERM` / `not-found` / `not-a-dir` / `out-of-root` / `root-unknown` / `root-unavailable`；`total` 是截断前总数，`truncated` 表示是否截断 |
| 权限判定 | `granted`、`source`、`message`、`hint` | `source` ∈ {`sandbox`,`bridge`,`unavailable`,`unknown-root`} |
| 权限申请结果 | 授权结果码、`granted`、`bridgeUnavailable`、`message` | 结果码：`0` 已授予 / `-1` 拒绝 / `2` 请求无效 |
| 创建结果 | `ok`、`code`、`message`、`path` | `code`：`exists` / `invalid-name` / `invalid-parent` / `out-of-root` / `create-failed` |

## 7. 假设与约束

- 三根路径由**服务端进程**解析：沙箱取宿主已改写的家目录；文档/下载取用户主目录常量（可用环境变量覆盖，便于测试）。
- 文档/下载权限为 `normal` 级 `user_grant`：装完不自动授予，需运行期请求一次；`RequestPermission` 在部分 PC 模式 runtime 上可能「回调成功但不弹窗、实际访问仍被拒」🔶（沿用 hos 结论）⇒ 事实判据是**列举成功**（FR-203-025）。
- 权限门只有两个按钮（需求硬要求），因此**不提供**「去系统设置」深链按钮；原因文案中提示用户可到系统设置调整。
- 渲染层为 ArkWeb 同源加载的网页（`platform === "web"`），对话框固定走应用内 `DirectoryPickerDialog`；不改 desktop 平台臂。
- 上游 `fs/find`（搜索/建议）在本平台不可用，三根模式下不依赖它（逐级展开是预期路径）。
- 本版**不做**主目录记忆与桌面根（§1.1）。
- **围栏是词法包含性判定，不是内核沙箱**（安全性质披露）：`isWithin`/`relativeFromRoot` 与插件侧的 `path.resolve` 前缀判定都不解析 symlink；本平台没有 symlink（规划 §8.4 / A4），且根路径只由插件解析、UI 不可注入。绕过 UI 直接调 `browse` 仍受根围栏约束，但直接调上游 `fs/list` 与现状同风险（本模块未扩大）。
- **`permissionRequest` 的 `ok` 语义**与其它方法不同：它表示「调用本身没有被宿主拒绝」，`granted` 才是授权结果；`code` ∈ `0`（已授予）/ `-1`（拒绝）/ `2`（请求无效）/ `timeout`（宿主侧上限内未回调）/ `bridge`（宿主能力故障）。超时与桥故障都必须如实呈现，不得折叠成「拒绝」或「已授予」。
- **新建文件夹的父目录 = 当前选中目录**（无选中则当前主目录根）。因此连续两次「新建」默认会在上一层新建的目录里再建一层——这是「在选中目录内新建」的一致语义，不是缺陷。
- **树内选中高亮不由本模块驱动**：上游 `@pierre/trees` 的公开 API 没有「按路径设置选中」，`selected` 只用于选择行与「打开」回传值；创建后选择行与回传值正确，行高亮由树自身的选择模型决定。
- 主目录切换与首次导航可能各触发一次列举（`navigation` 代次让后发者胜）：多一次只读 RPC，无副作用，未为此增加状态耦合。
