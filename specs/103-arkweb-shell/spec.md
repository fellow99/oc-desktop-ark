## 1 模块概述

### 1.1 目的

用应用内的系统 Web 容器承载「由本机服务同源渲染的标准界面」，并把启动中间态、失败态、诊断信息做成**应用内可见的壳**：
**加载页 → 就绪后切主界面 → 首屏成功清历史 → 全程导航围栏 → 失败进错误页/诊断面板**。

### 1.2 要解决的问题

| # | 问题 | 不解决的后果 |
|---|---|---|
| Q1 | 界面是单页应用，依赖本地存储与数据库能力 | 存储开关缺失 ⇒ 首屏直接崩（白屏） |
| Q2 | 服务在本机回环地址上，可能被容器判为不可达或明文被拦 | 永远加载不出主界面，且原因不可见 |
| Q3 | 容器会响应返回键与页面内跳转 | 用户可回到加载页/错误页，或把应用变成浏览器 |
| Q4 | 失败发生在容器内部（网络错误、HTTP 错误码） | 白屏、无文案，无法截图取证 |
| Q5 | 页面能力面未知（长连接、加密、worker、wasm、策略） | 「看着能开」但功能随机失效，无法归因 |

### 1.3 范围

- **在**：容器配置（存储/数据库/明文/脚本）、加载页与主界面切换、错误页、诊断面板、导航围栏、新窗口处理、历史清理、阶段文案展示、两项验收口径（回环可达、八项能力）。
- **不在**：服务端与运行时的启动（→ 101）、界面业务功能（在上游服务内）、鉴权令牌生成（→ 105）、外链目标应用的注册与权限（→ 104）。

## 2 用户故事

| # | 故事 | 关联需求 |
|---|---|---|
| US-1 | 作为用户，我打开应用先看到「正在启动 / 第 N 阶段」而不是白屏，并在服务就绪后自动切到主界面 | FR-103-003、FR-103-009 |
| US-2 | 作为用户，我在主界面按返回键不会退回加载页或错误页 | FR-103-004 |
| US-3 | 作为用户，点开界面里的外链会交给系统打开，而不是把应用变成浏览器 | FR-103-005、FR-103-012 |
| US-4 | 作为排障者，失败时我能看到阶段、原因和一段日志，并能截图给别人 | FR-103-007、FR-103-008 |
| US-5 | 作为评审者，我能看到「八项能力逐项通过/不通过」的记录，而不是一句「能用」 | FR-103-010 |

## 3 功能需求

> 关键词：MUST / SHOULD / MAY 按 RFC 2119 解释。

**FR-103-001（容器必备配置）**：渲染容器 MUST 启用脚本执行、**DOM 存储访问**与**数据库访问**；缺任一存储开关时 MUST 在诊断面板标注「存储能力可能不可用」，MUST NOT 以「能打开页面」作为通过判据。

**FR-103-002（回环可达与明文放行）**：容器 MUST 能加载本机回环地址上的明文 HTTP 页面；若平台默认拦截明文或不允许回环，MUST 通过清单配置放行，MUST NOT 改用局域网地址作为默认路径。判定口径：页面加载完成回调触发 **且** 页面内一次同源请求返回成功（P0-D）。

**FR-103-003（加载页与切换）**：首屏 MUST 是**应用内**加载页（不依赖本地服务）；主界面 MUST 只在模块 101 报告就绪后加载，加载地址 MUST 取自就绪结果（真实端口），MUST NOT 使用常量地址或上一轮地址；切换 MUST 幂等（一次启动只切一次）。

**FR-103-004（历史清理）**：首屏成功（加载完成回调 + 地址属于本机服务）后 MUST 清理一次导航历史，使返回键不再回到加载页/错误页；清理失败 MUST 记 warn 并保持可见（不静默）。

**FR-103-005（导航围栏）**：主框架导航 MUST 只放行两类：应用内本地页、本机服务地址；其余主框架导航 MUST 阻断并转交系统外链（FR-103-012）。子框架（内嵌框架/资源）MUST 放行 —— 拦子框架会破坏界面。

**FR-103-006（新窗口）**：页面请求新窗口（脚本打开/新标签）时 MUST NOT 静默丢弃：MUST 记录一条 warn，并把该请求改由当前容器承载，从而走 FR-103-005 的分流。

**FR-103-007（错误页）**：任一失败（就绪超时、加载失败、HTTP 错误码、崩溃记录）MUST 显示应用内错误页，内容至少含：失败阶段、原因摘要、日志尾（≥10 行）、以及「请重启应用」提示；错误页 MUST NOT 依赖本地服务渲染；MUST NOT 提供假的「重试启动」按钮。

**FR-103-008（诊断面板）**：壳 MUST 提供可随时打开的诊断面板，展示：状态、阶段、可渲染地址（或「(端口未就绪)」）、最近错误、日志尾（≥50 行）、诊断快照 JSON；面板 MUST 可从错误页进入，且 MUST NOT 暴露口令与完整鉴权 URL（只显示 `?auth_token=***`）。

**FR-103-009（阶段文案）**：加载页 MUST 显示模块 101 产生的阶段文案（中文，≥5 个阶段）；文案更新 MUST 与阶段推进同步；MUST NOT 出现「内测 / 测试 / 预览」字样（合规 G10）。

**FR-103-010（八项能力矩阵）**：模块 MUST 提供八项能力的逐项验收口径与记录：① `localStorage` ② `IndexedDB` ③ `fetch` ④ 事件流长连接（≥60 s）⑤ `crypto.subtle` ⑥ blob worker ⑦ wasm ⑧ CSP（含 `sha256-` 内联脚本）。每项 MUST 记录「通过/不通过 + 证据」；任一项不通过 MUST 在诊断面板标出，且 MUST 按 FR-103-011 处置。

**FR-103-011（零注入优先）**：壳 MUST 默认不注入任何脚本；仅当 FR-103-010 的某项被判定缺失且该缺失影响首屏时，MAY 在文档开始阶段注入最小补丁脚本，且 MUST 记录注入原因、注入内容摘要与移除条件。

**FR-103-012（外链与浏览器语义）**：外链 MUST 交给系统处理（系统浏览器或已注册应用）；应用 MUST NOT 在容器内打开任意站点，MUST NOT 声明「可浏览」类实体能力（合规 G2）。

**FR-103-013（AI 标识）**：壳 MUST 常驻一行可截图的 AI 生成内容提示文字，MUST NOT 被容器内容遮挡（合规 G6）。

## 4 关键实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `ShellView`（渲染容器） | 控制器句柄、当前地址、错误标志、历史已清标志 | 单实例；一次启动只切一次页 |
| `ViewConfig`（容器配置） | 脚本、DOM 存储、数据库、明文策略、调试开关 | 存储两项恒为开；release 关闭调试 |
| `BootPage`（加载页） | 阶段文案、详述、可重试的「重新探活」入口 | 应用内渲染；不依赖本地服务 |
| `MainView`（主界面） | 地址（含一次性凭据）、就绪来源 | 地址只来自就绪结果 |
| `ErrorPage`（错误页） | 阶段、原因、日志尾、重启提示 | 不依赖本地服务；无假重试 |
| `DiagnosticPanel`（诊断面板） | 状态、阶段、地址、错误、日志尾、快照 | 脱敏；随时可开 |
| `NavigationFence`（导航围栏） | 放行集合、判定结果、是否主框架 | 默认拒绝；子框架放行 |
| `CapabilityMatrix`（能力矩阵） | 8 项 × {结论, 证据, 时间} | 逐项可证伪；缺项必须显式标红 |
| `StageNotice`（阶段文案） | 序号、中文文案 | 由 101 产生、本模块只渲染 |

## 5 验收场景

**AS-103-01 首屏不是白屏**（FR-103-003/009）
- Given 应用刚启动、服务未就绪
- When 首屏渲染完成
- Then MUST 看到应用内加载页与该阶段文案；主界面 MUST NOT 已开始加载

**AS-103-02 就绪后切换**（FR-103-003）
- Given 模块 101 报告就绪并给出地址
- When 壳执行加载
- Then 容器地址 MUST 等于该地址；MUST 只有一次加载调用（重复就绪事件不重复切页）

**AS-103-03 历史清理**（FR-103-004）
- Given 主界面首屏加载完成且地址属于本机服务
- When 用户按返回键
- Then MUST NOT 回到加载页/错误页；清理失败时 MUST 在日志与诊断面板可见

**AS-103-04 外链分流**（FR-103-005/012）
- Given 主界面内一个外部链接被点击
- When 容器收到主框架导航请求
- Then MUST 阻断容器内打开，并 MUST 转交系统处理；子框架请求 MUST 放行

**AS-103-05 新窗口不静默**（FR-103-006）
- Given 页面脚本请求新窗口
- When 容器收到该请求
- Then MUST 记录 warn，并在当前容器内承载后按 FR-103-005 分流

**AS-103-06 失败可见**（FR-103-007/008）
- Given 就绪超时或首屏加载返回 5xx
- When 失败被捕获
- Then MUST 切到错误页并显示阶段 + 原因 + 日志尾 + 「请重启应用」；诊断面板 MUST 可打开，且其中地址 MUST 显示为 `?auth_token=***`

**AS-103-07 回环可达（P0-D）**（FR-103-002）
- Given 应用内起一个最小 HTTP 服务
- When 容器加载该回环地址
- Then MUST 观测到加载完成回调 **且** 页面内同源请求成功；任一不满足即判 P0-D 红，MUST 记录证据并改用回退路线（由 101/网络决策承接）

**AS-103-08 八项能力（P0-E）**（FR-103-010）
- Given 主界面已可交互
- When 逐项执行能力探针（含事件流保持 ≥60 s）
- Then MUST 产出 8 行「结论 + 证据」；任一项不通过 MUST 在诊断面板标红并进入 FR-103-011 决策

**AS-103-09 无浏览器语义**（FR-103-012）
- Given 应用清单与能力声明
- When 检查可浏览类实体/动作声明
- Then MUST 不存在该类声明（合规 G2）

## 6 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 加载页到主界面的切换 MUST 在就绪后 ≤ 1 s 内发起；诊断面板打开 MUST ≤ 500 ms（只读内存快照） |
| 可靠性 | 容器回调 MUST 不抛异常打断渲染；重复回调 MUST 幂等；任一失败 MUST 有可见落点 |
| 可观测 | 每次导航判定（放行/阻断 + 原因）、每次切页、每次清历史 MUST 各有一条结构化日志 |
| 安全 | 只允许本机服务与本地页；调试开关在 release 关闭（宪法 S5）；凭据脱敏（S2/S3） |
| 可测试 | 界面判据 MUST 可用截图 + 布局转储差异 + HTTP 端点三种手段复核（不用「看起来正常」） |
| 兼容 | 八项能力缺失 MUST 逐项记录，不因一项缺失而把整体判为不可用（除非影响首屏） |

## 7 假设与约束

- 界面由**本机服务同源**提供，壳不实现任何业务路由（宪法 C1）。
- 回环可达性属于**未裁决冲突**（规划 §5.4 X1）：本模块只给验收口径，路线选择由 P0-D 结果决定。
- 能力面属于**未知项**（规划 §5.3 / §11 P0-E）：缺失项用注入兜底是「例外路径」，必须留证。
- 容器的下载、定位、媒体等能力不在 v1 范围，不申请对应权限；错误页与诊断面板必须能在「服务完全不可用」时工作，因此不得依赖本地服务。
