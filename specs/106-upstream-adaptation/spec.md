## 1 模块概述

### 1.1 目的

让上游 **stock 产物**在本地运行时上「能加载、能常驻、能少打补丁」：
以**最小、幂等、可逆**的补丁把平台差异收敛在构建期，运行期只消费一份未分叉的产物。

### 1.2 要解决的问题

| # | 问题 | 不解决的后果 |
|---|---|---|
| Q1 | 上游默认按更高版本的运行时构建 | 产物用了本运行时没有的语法/内置模块，加载即失败 |
| Q2 | 平台标识不是上游认识的任何分支 | 平台专用实现永不命中，落到不可用的默认实现 |
| Q3 | 某能力模块在**模块顶层**加载原生库 | 一个不可用的能力把**整份产物**的加载拖垮 |
| Q4 | 构建条件只看普通解析、漏了另一条解析链 | 服务端产物里仍解析到错误变体，问题只在运行期暴露 |
| Q5 | 两套工程共用一个上游工作树 | 「别人打的补丁」被误判成「自己打的」，构建不可复现 |
| Q6 | 数据库能力被误判为缺失 | 引入不必要的原生依赖（自建 ABI 产物、体积与合规成本） |

### 1.3 范围

- **在**：基线锁定与工作树守卫、补丁集的必要性与幂等判据、构建条件与目标版本、PTY/常驻 PTY 打桩、SQLite 零补丁结论、原生件与 ABI 边界、shell 解析的不可读语义、产物可加载性判据。
- **不在**：补丁内容之外的业务实现（→ 101/102）、载荷投放与体积（→ 102）、权限与合规材料（→ 107）、运行时二进制本身的构建（库负责）。

## 3 功能需求

> 关键词：MUST / SHOULD / MAY 按 RFC 2119 解释。

**FR-106-001（基线锁定）**：补丁应用与构建 MUST 校验上游 `HEAD` 等于锁定基线（`9b4ec5714d`）；不符 MUST 拒绝执行且 MUST NOT 修改任何文件；覆盖基线 MUST 只能经显式环境变量。

**FR-106-002（工作树守卫）**：补丁前 MUST 要求工作树干净（无已跟踪改动、无未跟踪文件）；不干净 MUST 拒绝执行并提示「可能是另一个工程留下的改动」；丢弃改动 MUST 只能经显式确认参数。

**FR-106-003（幂等判据）**：每条补丁 MUST 以「反向校验成功」判定为已应用并跳过；MUST NOT 以文件内容猜测、MUST NOT 重复应用。

**FR-106-004（不留半应用）**：应用后 MUST 立即做反向校验；校验失败 MUST 报错并停止后续补丁；MUST NOT 留下「一半补丁已打、一半未打」的构建输入。

**FR-106-005（补丁集最小化）**：v1 补丁集 MUST 恰为 3 条：`0001`（构建条件与目标）与 `0003`（PTY 打桩）为**必需**，`0006`（shell 解析）为**条件必需**；编号 MUST 沿用既有编号且缺号 MUST NOT 回填；新增补丁 MUST 追加到列表末尾。

**FR-106-006（平台变体优先）**：构建条件 MUST 让平台专用变体先于通用变体命中，且 MUST 同时作用于**普通解析**与**服务端/SSR 解析**两条链；只改一处 MUST 视为未完成。

**FR-106-007（目标版本可注入）**：构建目标 MUST 由环境变量注入并固定为运行时的大版本（`node24`）；MUST NOT 使用上游默认目标；目标值 MUST 写入构建日志与产物清单。

**FR-106-008（中性兼容层）**：若补丁包含跨版本的导出兼容层，MUST 在新版本上自动走原函数且 MUST NOT 改变非 SEA 路径行为；MUST NOT 以「兼容」为由扩大改动面。

**FR-106-009（PTY 打桩）**：终端与常驻终端两个能力变体 MUST 提供打桩实现：能力标志 MUST 为「不支持」、调用 MUST 抛出可读原因；MUST NOT 伪造可用的终端。

**FR-106-010（消除顶层原生加载）**：打桩 MUST 使对应模块不再在**模块顶层**加载任何原生库；否则一个能力不可用会中断整份产物的加载（这是打桩的**验收判据**，不是实现偏好）。

**FR-106-011（SQLite 零补丁）**：数据库能力 MUST 使用运行时内置实现，MUST NOT 新增第三方数据库绑定、MUST NOT 为数据库新增补丁；该结论 MUST 由二进制证据（运行时内含对应符号）与 host 侧交叉验证支撑。

**FR-106-012（原生件与 ABI）**：产物 MUST 不含需要在设备上现场加载的第三方原生扩展；若未来引入，其 ABI MUST 与运行时一致（当前 137）且 MUST 走「先复制到可写目录再加载」的规则；v1 MUST NOT 引入原生扩展。

**FR-106-013（shell 判定）**：`0006` MUST 按可证伪判据决定去留：若设备上出现「会话可建、消息可发、助手永不回复且日志为权限错误」则 MUST 应用；若正常回复则 MUST NOT 应用；判定 MUST 记录设备、日期、现象与结论。

**FR-106-014（不可读即不可用）**：shell 解析 MUST 把「不可读」与「不存在」一视同仁（都视为该 shell 不可用）；MUST 支持通过环境变量指定回落 shell，且回落值 MUST 是设备上真实可执行的绝对路径。

**FR-106-015（换基线新建目录）**：更换上游基线 MUST 新建 `patches/<新 tag>/` 并重新生成补丁；MUST NOT 就地修改历史补丁或旧目录。

**FR-106-016（产物可加载）**：产物 MUST 能被运行时不中断地 `import`，并 MUST 打印监听地址；任何顶层异常（缺导出、原生加载失败、缺失模块）MUST 视为失败，MUST NOT 以「先跑起来再说」通过。

**FR-106-017（状态报告）**：补丁检查 MUST 输出三种可区分状态（已应用 / 可应用 / 冲突）与汇总计数；存在冲突 MUST 以非零退出码结束；MUST NOT 把「冲突」报告成「可应用」。

**FR-106-018（可逆与上下文纪律）**：补丁 MUST 能正反向往返并还原到逐字节一致；新补丁 MUST NOT 落在既有补丁上下文区间（前后各 3 行）内；MUST NOT 使用三方合并强行落地。

## 4 关键实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `PatchEntry`（补丁条目） | 编号、落点、作用、必要性、SHA-256、是否已应用 | 编号单调；缺号不回填；SHA 与文件一致 |
| `Baseline`（上游基线） | tag、提交、分支 | 与应用/构建校验同源；换基线=新建目录 |
| `BuildTarget`（构建目标） | 运行时大版本、注入变量名、实际值 | 与运行时大版本一致；写入日志与清单 |
| `VariantMapping`（变体映射） | 变体名、平台条件、命中文件、是否打桩 | 平台条件先于通用条件；打桩项不得有顶层原生加载 |
| `Artifact`（产物） | 入口文件、资源目录、文件数、SHA-256、目标版本 | 可被 `import`；不含现场加载的原生扩展 |
| `RuntimeLock`（运行时锁定） | 版本、模块 ABI、SONAME、部署文件名、哈希 | ABI 与产物/原生件一致；哈希可复核 |
| `DecisionRecord`（判定记录） | 判据、设备、日期、现象、结论、是否打补丁 | 结论可复现；改动必须回写规划 |

## 5 验收场景

**AS-106-01 补丁检查全绿**（FR-106-001/003/017，TC-S-001/003）
- Given 干净的上游工作树且 HEAD = 锁定基线；When 执行补丁检查；Then MUST 输出「基线正确」「工作树干净」，三条补丁 MUST 各为「已应用」或「可应用」，冲突数 MUST 为 0

**AS-106-02 干净基线往返**（FR-106-004/018）
- Given 干净基线；When 按编号顺序应用全部补丁再逐条反向校验；Then MUST 全部通过，改动 MUST 只落在补丁声明的落点，反向还原后 MUST 与基线逐字节一致

**AS-106-03 产物可加载**（FR-106-006/007/016，P0-C）
- Given 已应用补丁并按 `node24` 目标构建；When 在运行时内 `import` 产物；Then MUST 不中断并打印监听地址，MUST NOT 出现「缺少导出 / 缺少模块 / 原生加载失败」

**AS-106-04 基线不符**（FR-106-001）
- Given HEAD 不是锁定基线；When 执行补丁；Then MUST 以非零退出码失败、提示新建补丁目录，且 MUST NOT 修改工作树

**AS-106-05 脏工作树**（FR-106-002，TC-S-002）
- Given 工作树有未提交改动；When 执行补丁检查；Then MUST 拒绝并提示「可能是另一个工程的改动」；未给显式确认时 MUST NOT 清理或还原

**AS-106-06 终端不可用但不崩**（FR-106-009/010）
- Given 产物已打 PTY 打桩；When 界面请求打开终端；Then MUST 返回「不支持 + 原因」，应用 MUST 继续运行，MUST NOT 在加载期崩溃

**AS-106-07 SQLite 零补丁可用**（FR-106-011/012，TC-H-007/P0-B）
- Given 产物未包含任何第三方数据库绑定；When 建库、写入、重启后再读；Then MUST 读到上次写入的会话，MUST NOT 出现「无此绑定」类错误

**AS-106-08 shell 判定可复现**（FR-106-013/014，P0-J）
- Given 设备上发起一次真实对话；When 观察助手是否回复与日志；Then 若出现权限错误且不回复 MUST 应用 `0006` 后复测通过，若正常回复 MUST NOT 应用并记录「不命中」，两种情况 MUST 都有判定记录

**AS-106-09 ABI 与原生件核对**（FR-106-012）
- Given 完成产物收集；When 扫描产物中的原生扩展与运行时 ABI；Then 产物 MUST 不含 `.node` 等需现场加载的扩展，运行时 ABI MUST 报告为 137，MUST NOT 出现 ABI 不匹配提示

## 6 非功能需求

| 类别 | 要求 |
|---|---|
| 可复现 | 补丁 SHA-256、基线提交、构建目标、产物清单 MUST 全部留档；同一输入 MUST 得到同一补丁集合 |
| 最小改动 | 每条补丁 MUST 只做必要改动；能用环境变量/条件变体解决的 MUST NOT 打补丁 |
| 可逆 | 正反向往返 MUST 还原到逐字节一致；MUST NOT 残留临时文件 |
| 可审计 | 必要性、根因、判定 MUST 写在补丁目录 README；新增/删除补丁 MUST 有理由 |
| 互斥 | 上游工作树同一时刻 MUST 只有一个工程处于「已打补丁」状态；构建 MUST 串行 |
| 兼容 | 目标运行时 MUST 与锁定文件一致（版本 / ABI / SONAME）；不一致 MUST 在构建期暴露 |

## 7 假设与约束

- 上游基线固定为 `v2.0.26` / `9b4ec5714d`；不 fork、不引入长期分支（宪法 C4）。
- 运行时版本为 24 系、模块 ABI 137、平台标识不是上游任何既有分支（规划 §2.3）。
- 设备侧不执行自带 ELF；因此常驻终端助手与任何外部二进制路线都不可用。
- PTY 平台级不可用（SELinux 拒绝），打桩是「如实降级」而非临时绕过。
- 数据库能力已由运行时内含符号判定可用（host 侧证据）；设备侧只剩运行期行为（WAL/文件锁）待复验。
- 上游工作树被两个工程共用，故必须基线 + 工作树双守卫、串行构建。
- 构建机固定 bun 1.3.14（TECH.md）；工具链漂移会导致产物差异，不在本模块兜底。
