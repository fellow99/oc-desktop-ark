## 1 模块概述

### 1.1 目的

让界面在**不需要用户手工登录**的前提下进入受口令保护的本机服务，并让凭据在**重启后仍然有效**：
宿主生成一次口令 → 安全持久化 → 只经进程环境交给服务端 → 首屏导航携带一次性凭据 → 之后由前端自行持有。

### 1.2 要解决的问题

| # | 问题 | 不解决的后果 |
|---|---|---|
| Q1 | 服务端**强制要求口令**，缺失即启动失败 | 不注入口令 ⇒ 服务端起不来，界面白屏 |
| Q2 | 口令若每次启动重新生成 | 前端持久化的凭据立即过期，用户每次都要重新登录 |
| Q3 | 口令若进入日志/诊断/错误页 | 同机其它进程或截图即可取得完整控制权 |
| Q4 | 首屏没有任何凭据 | 用户被挡在登录页，无法进入会话列表 |

### 1.3 范围

- **在**：口令生成、持久化与轮换；口令注入；首屏一次性凭据；就绪探活；配对 Cookie 备选；失败语义；日志脱敏；凭据文件权限。
- **不在**：渲染壳与导航围栏（→ 103）、启动编排与状态机（→ 101）、宿主能力（→ 104）、模型 API Key 的存储（上游设置页负责）。

## 3 功能需求

> 关键词：MUST / SHOULD / MAY 按 RFC 2119 解释。

**FR-105-001（口令必填）**：应用 MUST 始终向服务端提供非空口令；服务端因缺口令拒绝启动时，应用 MUST 进入可见失败态并说明原因，MUST NOT 把「服务端起不来」显示为「正在加载」。

**FR-105-002（生成）**：口令 MUST 由密码学随机源生成，熵 MUST ≥ 256 位，编码 MUST 可直接用于 URL 查询参数与 Basic 凭据（无保留字符）；MUST NOT 使用时间戳、设备标识或固定值。

**FR-105-003（持久化）**：口令 MUST 持久化到应用私有目录下的独立文件，结构 MUST 含结构版本、口令、首次生成时间、最近轮换时间；文件权限 MUST 为「仅属主可读写」，写入 MUST 原子（临时文件 + 重命名）并在写入后回读校验。

**FR-105-004（跨启动稳定）**：除轮换外，口令 MUST 在多次启动之间保持一致；界面重载、重新导航、重新探活 MUST NOT 改变口令。

**FR-105-005（注入方式）**：口令 MUST 只经进程环境变量交给服务端；MUST NOT 写入命令行参数、HAP 内资源、日志、崩溃记录、诊断快照或错误页。

**FR-105-006（首屏一次性凭据）**：首屏导航 MUST 携带一次性凭据参数，其值 MUST 等价于 `base64("opencode:" + 口令)`；前端消费后 MUST 立即从地址栏移除该参数（由前端自身完成，宿主不额外注入）。

**FR-105-007（就绪探活）**：加载首屏前 MUST 以 `Basic` 凭据请求服务端健康端点，只有返回 `200` 且含版本字段才算就绪；探活失败 MUST 记录状态码与原因，并 MAY 退化为「交给首屏自行处理」，但 MUST NOT 静默当作成功。

**FR-105-008（配对备选）**：当首屏一次性凭据不可用时，MUST 能改用配对通道：以 `Basic` 凭据申请短期一次性配对码 → 以**同源导航**兑换 → 获得会话 Cookie。Cookie 名 MUST 按端口区分（`opencode_session_<port>`），属性 MUST 为 httpOnly、sameSite=lax、路径 `/`、有效期 30 天。

**FR-105-009（Cookie 同源约束）**：会话 Cookie MUST 只在同源请求上生效；MUST NOT 依赖跨源携带；MUST NOT 把 Cookie 当作可跨端口复用的凭据。

**FR-105-010（轮换语义）**：轮换 MUST 只发生在「用户主动重置」或「凭据文件损坏」两种情况；轮换后 MUST 使旧会话全部失效（会话令牌由口令派生），并 MUST 告知用户「需要重新登录」。

**FR-105-011（损坏处理）**：凭据文件不可解析、字段缺失或长度不足时，MUST 先备份坏文件、再重新生成，并 MUST 记录原因与提示；MUST NOT 静默替换为任何已知/默认口令。

**FR-105-012（日志脱敏）**：任何日志、诊断、错误页 MUST 把鉴权参数显示为 `?auth_token=***`；MUST NOT 打印 `Authorization` 头值、Basic 串、口令本身；MUST NOT 打印可反推出凭据的哈希前缀。

**FR-105-013（失败可见）**：口令不匹配 MUST 表现为可见失败：至少含「凭据不匹配」阶段文案、服务端返回状态、以及「重置凭据」入口；MUST NOT 停在无文案的空白页。

**FR-105-014（不落明文）**：除凭据文件外，口令 MUST NOT 出现在任何可被其他应用读取的位置（共享目录、缓存、剪贴板、上传内容、崩溃报告）。

**FR-105-015（零注入）**：v1 MUST NOT 引入请求头改写、请求代理或页面脚本注入来实现鉴权；免手工登录 MUST 只依赖首屏一次性凭据（备选为配对 Cookie）。

**FR-105-016（重试语义）**：就绪探活失败后的重试 MUST 复用同一口令，MUST NOT 通过重置口令来「修复」探活失败（重置是用户动作）。

**FR-105-017（凭据与目录授权分离）**：凭据文件 MUST 只存口令相关字段；目录授权记录 MUST 另存，二者 MUST NOT 混在同一文件（避免把口令写进可分享的授权数据）。

## 4 关键实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `Credential`（本地凭据） | 结构版本、口令、首次生成时间、最近轮换时间 | 口令熵 ≥ 256 位；跨启动稳定；权限仅属主 |
| `AuthToken`（一次性凭据） | 编码值、来源口令、使用次数 | 只在首屏导航使用一次；日志中恒为 `***` |
| `SessionCookie`（会话 Cookie，备选） | 名称（含端口）、值、有效期、同源约束 | 仅同源生效；不跨端口复用 |
| `ProbeResult`（探活结果） | 是否就绪、状态码、版本、失败原因、尝试次数 | 只有 200 + 版本才算成功 |
| `AuthFailure`（鉴权失败） | 阶段、状态码、原因、下一步 | 必须可截图、可定位 |
| `RotationRecord`（轮换记录） | 触发原因、时刻、旧会话是否撤销 | 只有两种触发原因；轮换即撤销 |

## 5 验收场景

**AS-105-01 首启直接进会话列表**（FR-105-006/007，TC-D-006）
- Given 首次启动、无历史凭据
- When 首屏加载完成
- Then MUST 出现会话列表（非登录页）；MUST NOT 要求用户输入口令

**AS-105-02 重启免登录**（FR-105-003/004，TC-D-007）
- Given 上次运行已生成并持久化口令
- When 杀进程后重启
- Then MUST 仍免登录；凭据文件内容 MUST 与上次一致（除轮换）

**AS-105-03 错口令失败可见**（FR-105-013，TC-D-008）
- Given 人为篡改凭据文件中的口令；When 启动并探活；Then MUST 出现「凭据不匹配」类失败态（含状态码）+ 重置入口，MUST NOT 白屏

**AS-105-04 无凭据被拒**（FR-105-001、009，TC-H-008）
- Given 请求不带任何凭据；When 访问受保护接口；Then MUST 返回 `401`，应用侧 MUST 把该失败如实计入探活结果

**AS-105-05 日志脱敏**（FR-105-012/014）
- Given 完整启动 + 一次首屏加载 + 一次失败
- When 检索日志、诊断快照、错误页文本
- Then 口令与完整鉴权地址 MUST 零命中；只允许出现 `?auth_token=***`

**AS-105-06 轮换即撤销**（FR-105-010）
- Given 已取得旧会话（Cookie 或旧凭据）
- When 用户执行重置
- Then 旧会话 MUST 失效（旧凭据请求返回 `401`）；界面 MUST 提示重新登录

**AS-105-07 配对备选可用**（FR-105-008）
- Given 首屏通道被判定不可用
- When 走配对通道完成同源导航兑换
- Then 服务端 MUST 下发按端口命名的会话 Cookie；后续同源请求 MUST 免凭据通过

**AS-105-08 文件权限与结构**（FR-105-003）
- Given 已生成凭据；When 读取凭据文件与权限位；Then 结构 MUST 含版本/口令/两个时间戳，权限 MUST 仅属主可读写，写入后回读校验 MUST 通过

## 6 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 口令不出私有目录；日志零明文；只监听回环（路线 B 时必须有密码 + 随机端口 + 界面提示） |
| 可靠性 | 生成/读取/写入 MUST 不因单次 IO 失败而永久损坏凭据；写入失败 MUST 可见且不改变既有有效口令 |
| 可观测 | 每个阶段（生成/复用/轮换/注入/探活/导航）MUST 有一条结构化日志，且 MUST 不含敏感值 |
| 性能 | 凭据读取与口令生成 MUST NOT 让启动出现可感知停顿（相对运行时启动耗时可忽略） |
| 兼容 | 首屏通道 MUST 不依赖宿主 Cookie 能力；Cookie 备选 MUST 在能力缺失时降级为「一次性导航」并如实上报 |
| 可审计 | 每次轮换 MUST 留下「原因 + 时刻 + 是否撤销旧会话」记录，供诊断面板与回归核对 |

## 7 假设与约束

- 服务端**永远有口令**（上游契约）；本模块不实现「免密模式」。
- 一次性凭据会短暂出现在地址栏，前端读取后立即移除（上游行为）；因此宿主侧只需保证**不记录**。
- v1 不提供登录界面：用户不输入口令，口令完全由宿主管理（`overall-spec.md` FR-AUTH-003）。
- 网络路线默认回环；若探针判定必须走局域网，则口令与随机端口是唯一防线，界面 MUST 提示可达范围。
- Cookie 备选依赖宿主 Web 容器的 Cookie 能力（⬜ P0-E）；不可用时降级为一次性导航。
- 系统时间可信（Cookie 有效期判断依赖它）；时钟异常 MUST 表现为可见失败，而非静默放行。
- 目录授权与本模块无关（→ 104）；凭据文件 MUST NOT 承载授权数据（FR-105-017）。
