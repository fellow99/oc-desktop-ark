# 上架合规（107-compliance）—— 规格

> **模块**：`107-compliance` ｜ **状态**：Proposed ｜ **日期**：2026-10-18 ｜ **应用**：OC Desktop Ark / `org.fellow99.oc.OCDesktopArk`
> **依据**：`docs/000-工程规划.md` v0.3 §13（G1–G11）、§10（ACL 与权限）、§5.11（命名与签名）、§12.1 R10（材料口径）；`specs/constitution.md`（C1–C6、S1–S7）｜ **证据口径**：✅ 实测 ｜ 🔶 沿用 ｜ ⬜ 待验证
> **技术无关**：本文件只写「要满足什么 + 怎么判定」；脚本、命令、落点见 [`plan.md`](./plan.md)。

## 1. 概述
把上架清单从「一组描述」变成**逐条可判定**的检查项：每条有唯一 ID、唯一判据、可指认的证据落点；任一不满足即阻断提审。合规在本工程里不是文档工作，而是**发布门禁**。

**包含**：G1–G11（ArkWeb 渲染、无浏览器语义、包内无内核、第三方许可、ELF 合规、AI 标识、图标/命名/备案三一致、隐私链接、PoC 清理、文案禁用词、不得绕签名）；ACL 三项（JIT 可写可执行内存 / 剪贴板读 / 桌面目录读写）+ 开放权限 + 用户授权目录 + `definePermissions` 成对声明；「声明面 = 使用面」的比对与豁免登记；复审材料口径的单一表述。

**不包含**：ACL 工单办理/配额/审核周期（归 `docs/ACL申请清单.md`）；隐私政策文本的法务内容（只判「可达」与「登记一致」）；商店后台点选提交（人工）；回归四件套的采集与阈值（归 `109-regression`）。

### 1.1 与其它模块的边界

## 3. 功能需求
> 级别：MUST / MUST NOT / SHOULD（RFC 2119）。编号 `FR-107-NNN` 一经分配永不复用。

### 3.1 渲染形态与浏览器语义（G1–G3）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-001 | 主界面 MUST 由应用进程内的系统 Web 组件（ArkWeb）渲染；MUST NOT 使用第三方浏览器内核，MUST NOT 随包携带 Chromium / Electron 类运行时（G1、G3） | HAP 内原生库清单只含 Node 运行时与 C++ 运行库；浏览器内核类库名零命中 |
| FR-107-002 | 应用 MUST NOT 具备浏览器语义（G2）：ability 的 skills MUST NOT 声明 `entity.system.browsable`，MUST NOT 声明 `ohos.want.action.viewData`，MUST NOT 注册 URL 深链入口 | 源文件与包内 `module.json` 双处断言零命中；反向注入必须失败 |
| FR-107-003 | 全部界面 MUST 来自本机服务的同源地址；MUST NOT 提供地址栏、多标签、书签等浏览入口；外链 MUST 交由系统能力打开（G1） | 壳层组件清单无地址栏/标签容器；外链调用点只经宿主能力 |
| FR-107-004 | 上架版本 MUST NOT 包含任何绕过平台代码签名或可执行内存控制的组件（G11）；相关 PoC MUST 与发布分支物理隔离 | 发布分支与包内制品检索零命中；隔离以目录/分支事实核对 |

### 3.2 第三方许可与 ELF 合规（G4–G5）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-005 | 发布包 MUST 附第三方许可清单：运行时（MIT，含 V8/OpenSSL/ICU 等）、上游应用（MIT）、全部随包 JS 依赖；并 MUST 给出原生运行库的来源与 SHA-256（G4） | 清单条目与包内依赖逐项对应；许可文件在包内可达 |
| FR-107-006 | 随包原生库 MUST 全部登记（名称 / 来源 / SHA-256 / 许可）；MUST NOT 随包分发并执行自有可执行文件；MUST NOT 申请二进制证书或外部原生代码类权限（G5） | 原生库集合与登记表一一对应；禁止项清单零命中 |
| FR-107-007 | 非官方声明与许可声明 MUST 在 `README` 与应用内「关于」页同时可见 | 两处文本存在且语义一致（逐字比对口径见 plan §3） |

### 3.3 AI 标识与文案（G6、G10）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-008 | AI 生成内容标识 MUST 常驻可见（壳层灰字，不依赖页面滚动位置与会话内容），且 MUST NOT 可被页面内脚本移除（G6） | 两次 `dumpLayout` 差异断言：首屏与滚动后该节点均存在；隐藏该节点时断言必须失败 |
| FR-107-009 | 首启与全量文案 MUST NOT 出现「内测 / 测试 / 预览版 / Beta / 试用」等字样（G10） | 壳层三套 locale + 载荷品牌文案全量检索零命中 |
| FR-107-010 | 文案 MUST NOT 使用受限平台/第三方指称作为本应用能力或名称的描述（禁用词表由本模块单点维护） | 禁用词表逐项检索零命中；命中即失败并给出文件与行号 |

### 3.4 图标、命名、备案与版本（G7）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-011 | 显示名 / 包名 / 备案主体 MUST 三处一致且已冻结；`AppScope/app.json5` 与三套 locale 的 `EntryAbility_label` MUST 逐字相同；改名 MUST 视为新建应用（需重新备案与重新申请 ACL） | 三处取值逐字相等；旧名零命中 |
| FR-107-012 | `versionCode` MUST 严格递增并与 `versionName` 同源（`major*10000+minor*100+patch`）；提审包 MUST 使用发布证书 + 发布 Profile | 取值符合规则且大于上一版登记值；Profile 类型为发布 |
| FR-107-013 | 图标 MUST 为 1024×1024、纯色不透明（无 Alpha）；包内图标与提审上传件 MUST 为同一文件 | 尺寸与 alpha 通道断言；两处 SHA-256 相同 |
| FR-107-014 | 提审材料 MUST 提供可用测试能力：测试账号/Key + 图文指引（G7） | 材料清单中该项有可指认条目与验证方式 |

### 3.5 隐私链接、PoC 清理与绕行（G8–G9、G11）

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-015 | 隐私声明链接 MUST 可达（MUST NOT 为空 URL / `about:blank` / 死链） | 真机点击后到达页面，页面标识命中登记值 |
| FR-107-016 | 发布包 MUST NOT 含样例 Ability、探针页面/端点、调试开关、远程调试参数（G9、`S5`） | 包内 ability 清单仅目标 Ability；运行时调试端口未监听；相关字符串零命中 |
| FR-107-017 | 清理结果 MUST 可证伪且可复跑：任一残留 MUST 使门禁失败，MUST NOT 仅靠人工目检 | 反向用例（注入残留）必须失败 |

### 3.6 权限与 ACL

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-018 | 三项受限权限 MUST 按本包名申请并声明：JIT 可写可执行内存、剪贴板读、桌面目录读写；JIT 一项 MUST 同时出现在 `requestPermissions` 与 `definePermissions`（成对，缺一即安装失败） | 声明数量与配对断言；真机不带 `--jitless` 启动无 SIGTRAP |
| FR-107-019 | 开放权限 MUST 按真实需要最小化声明（网络、网络信息、后台保活）；文档/下载目录 MUST 走运行期用户授权并如实提示 | 声明集合与使用点一一对应；未授权时给出可读拒绝 |
| FR-107-020 | ACL 未获批时应用 MUST 如实失败（错误页给出原因与下一步）；MUST NOT 以关闭 JIT 的方式「先跑起来」 | 无 ACL 的 Profile 下启动失败可见；源码中无 `--jitless` 兜底路径 |
| FR-107-021 | 每个声明项 MUST 有可指认的使用点（`文件:函数`）或登记在案的豁免理由；脚本 MUST 输出双向差集，任一方向非空即失败（豁免项除外） | 差集报告为空，或差集项全部命中豁免表（`S4`） |

### 3.7 材料口径与留痕

| 编号 | 需求 | 判据 |
|---|---|---|
| FR-107-022 | 复审材料 MUST 使用统一表述：「主界面是应用自带本地界面，由 ArkWeb 加载本机服务，非浏览器上网」；该表述 MUST 在 README、应用内「关于」页与提交材料三处一致，MUST NOT 出现互相矛盾的说法 | 三处文本逐字比对；矛盾表述检索零命中 |
| FR-107-023 | 合规结论 MUST 逐条对应 G1–G11 与 ACL 项，每条记录「结论 / 证据路径 / 日期 / 设备」；MUST NOT 使用「应该满足」「基本没问题」类表述 | 清单结构化字段齐备；缺失字段即视为未完成 |
| FR-107-024 | 门禁 MUST 只读、可重复执行且结论一致；同一输入的两次执行 MUST 给出相同结果 | 两次运行报告逐项相同（时间戳除外） |

| 实体 | 字段 | 说明 |
|---|---|---|
| `ComplianceItem` | `id`（G1–G11 / ACL-1..3）/ `requirement` / `status`（pass/fail/skip）/ `expected` / `actual` / `evidence` / `date` / `device` | 清单唯一单元；`skip` 必须带原因 |

## 5. 验收场景

1. **渲染形态与内核（正常 + 负例必存）**：真实包原生库清单通过；注入一个浏览器内核命名的库 → 门禁失败（TC-H-010 扩展）。
2. **浏览器语义（负例必存）**：给 ability 加 `browsable` 或 `viewData` → 失败；移除后回到零命中。
3. **许可与 ELF 合规（正常 + 负例）**：许可清单覆盖全部依赖、原生库与登记表一致；删一条许可或塞入未登记 `.so` → 失败。
4. **AI 标识（正常 + 负例必存）**：首屏与滚动后均可见；移除节点 → 断言失败（TC-D-015）。
5. **首启文案（负例必存）**：在某套 locale 塞入「预览版」→ 全量检索命中并失败（TC-D-015）。
6. **三一致与版本（正常 + 负例）**：显示名/包名/备案主体一致、`versionCode` 递增；只改一处或不递增 → 失败。
7. **图标（负例必存）**：带 Alpha 或非 1024² → 失败；包内与上传件哈希不同 → 失败。
8. **隐私链接（正常 + 负例必存）**：可达；替换为 `about:blank` → 失败（TC-D-015 扩展）。
9. **PoC 清理（正常 + 负例必存）**：包内仅目标 Ability 且无调试端口；塞回样例 Ability 或 `--inspect` → 失败（TC-S-007）。
10. **ACL 正反证（正常 + 负例必存）**：三项到位、JIT 成对声明 → 启动无 SIGTRAP；缺 `definePermissions` 中一项 → 安装失败或门禁失败（TC-D-002 / TC-D-003）。
11. **声明面=使用面（正常 + 负例）**：差集为空或全部带豁免；加一个无使用点的权限 → 失败（TC-S-005）。
12. **材料口径一致（正常 + 负例）**：三处逐字相同；任一处出现矛盾表述 → 失败。
13. **清单可判定（正常）**：每条有证据路径与日期；任一字段缺失 → 报告 `skip` 且整体不得判 pass。

## 6. 非功能需求

| 编号 | 需求 | 级别 |
|---|---|---|
| NFR-107-001 | 门禁 MUST 只读工作树（不改文件、不触发构建），可重复执行 | MUST |
| NFR-107-002 | 单项失败 MUST 报「哪一项、期望什么、实际什么、证据在哪」，MUST NOT 只给失败计数 | MUST |
| NFR-107-003 | 全量 host 侧检查 SHOULD 在 60 s 内完成（不含真机取证） | SHOULD |
| NFR-107-004 | 证据 MUST 落盘（`docs/evidence/YYYY-MM-DD-*.md`），含原始 JSON 与复现命令 | MUST |
| NFR-107-005 | 人工判定项 MUST 附截图或 `dumpLayout` 片段；无证据的人工项 MUST 记为未完成 | MUST |
| NFR-107-006 | 禁用词表与材料口径 MUST 单点定义，并由同一脚本消费（避免多处维护漂移） | MUST |

## 7. 假设与约束

| # | 假设 / 约束 | 影响 |
|---|---|---|
| A1 | 分发目标是应用商店上架（D14），材料在 Phase 3 汇总 | 门禁必须早于提审可跑，但不阻塞 Phase 0–2 |
| A2 | 三项受限权限按本包名可获批，但周期不可控 | JIT 是关键路径；未获批时判 blocked 而非 fail |
| A3 | 提审使用发布证书 + 发布 Profile，debug 自签不满足 | 版本与 Profile 类型纳入断言 |
| A4 | 图标与合作方商标声明素材可获取 | 图标断言需要真实素材，缺素材即 blocked |
| A5 | 应用形态本身就是对 G1 的正面回应（ArkWeb 唯一渲染）；平台也不提供「可申请的权限」来解决执行/链接语义 | 无需准备「未使用 ArkWeb」的复审口径；不把 SELinux 语义问题转成权限问题 |
