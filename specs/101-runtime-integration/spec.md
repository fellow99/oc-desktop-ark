## 1 模块概述

### 1.1 目的

把「内嵌运行时」接成一条可判定、可诊断、可关停的启动链：
**校验运行时 → 组装启动参数 → 投递启动 → 判定就绪 → 交出可渲染地址 → 失败留证据 → 关停只做标记**。

### 1.2 要解决的问题

| # | 问题 | 不解决的后果 |
|---|---|---|
| Q1 | 启动调用返回「成功」其实只代表**已投递** | 界面把「投递成功」当「服务可用」⇒ 白屏或加载失败 |
| Q2 | 监听端口由系统随机分配，宿主事先不知道 | 猜端口 / 固定端口 ⇒ 冲突或加载到错误端口 |
| Q3 | 上一轮的就绪标记会残留 | 重启后读到旧端口 ⇒ 探活打向已消失的端口 |
| Q4 | 运行时崩溃后进程内没有重启路径 | 提供「重试」按钮 = 骗用户 |
| Q5 | 运行时二进制体积大、来源需锁定 | 版本漂移后行为不可复现，问题无法归因 |

### 1.3 范围

- **在**：运行时包（ohpm 双包）接入与锁值校验、启动参数与启动投递、就绪判定（标记 + 日志双通道）、阶段状态机、诊断快照（状态/阶段/地址/错误/日志尾/崩溃记录）、关停标记位、单实例约束。
- **不在**：载荷内容与投放形态（→ 102）、渲染容器与加载页/错误页视图（→ 103）、口令生成与鉴权（→ 105）、宿主能力实现（→ 104）。

## 3 功能需求

> 关键词：MUST / SHOULD / MAY 按 RFC 2119 解释。

**FR-101-001（启动两段式）**：启动 MUST 拆为「投递」与「就绪」两段：启动调用的返回 MUST 只表示**已投递**，MUST NOT 被任何视图当作可渲染依据；就绪 MUST 由独立判据产生（FR-101-002）。

**FR-101-002（就绪判据）**：就绪 MUST 由以下两条通道之一判定，且 MUST 记录命中的通道与证据行：
① 就绪标记文件存在、可解析、且 `port > 0`；
② 运行时日志中出现结构化就绪行并解析出 `port > 0`。
两条通道都超时（上限 SHOULD 为 180 s，轮询间隔 SHOULD 为 500 ms）MUST 进入失败态，MUST NOT 用任何常量端口顶替。

**FR-101-003（本轮隔离）**：判定 MUST 只采纳**本轮投递之后**产生的证据：投递前 MUST 作废上一轮就绪标记；日志解析 MUST 丢弃早于本轮投递时刻的行（时间戳不可解析的行 MAY 保留）。

**FR-101-004（运行时锁值校验）**：运行时引擎（`libnode.so`）MUST 来自 `oh-package.json5` 钉死的 `@fellow99/node-runtime` 包；构建期 MUST 校验包内 `libnode.so` 的 SHA-256 与体积和 `runtime.lock.json` 锁值一致，任一不符 MUST 硬失败并给出「换包或明确更新锁定文件」的处置说明；校验脚本 MUST 是唯一实现，且 MUST 幂等（重复执行结果一致）；宿主 MUST NOT 在 `entry/libs/` 手工投放同名 `.so`（运行时包与手工投放两种来源择一）。

**FR-101-005（依赖形态）**：运行时 MUST 以 ohpm registry 包接入（`@fellow99/node-bridge` + `@fellow99/node-runtime`），版本号 MUST 在依赖清单中钉死（MUST NOT 使用 `*` 或本地文件路径），MUST NOT 直接引用库源码目录。

**FR-101-006（阶段状态机）**：运行时状态 MUST 收敛为六态：`idle` / `starting` / `running` / `failed` / `stopping` / `stopped`；状态变更 MUST 单向（`failed` 与 `stopped` 为终态，不回到 `starting`），且每次转移 MUST 产生一条结构化日志。

**FR-101-007（阶段文案）**：每个启动阶段 MUST 有一句中文文案（≥5 个阶段），文案 MUST 同时出现在界面与日志中，且 MUST NOT 出现「内测 / 测试 / 预览」字样。

**FR-101-008（单实例）**：应用 MUST 单实例运行（重复启动复用同一实例）；运行时 MUST 只被投递一次，第二次投递 MUST 被显式拒绝并保留首次原因。

**FR-101-009（诊断快照）**：模块 MUST 提供一个只读诊断快照，至少含：状态、阶段、可渲染地址（未就绪时为「(端口未就绪)」占位）、最近错误、日志尾（≥50 行）、崩溃记录（若存在）；快照 MUST 不含口令与完整鉴权 URL。

**FR-101-010（崩溃终态）**：若存在崩溃记录，状态 MUST 进入 `failed`，界面 MUST 提示「请重启应用」；模块 MUST NOT 提供原地重启运行时的能力。

**FR-101-011（关停）**：关停 MUST 只发出关停请求（含原因）并记录结果；实现 MUST 如实上报「运行时不会因此停止，真正停止只能靠进程退出」，MUST NOT 声称已优雅退出。

**FR-101-012（不新增第二个宿主）**：模块 MUST NOT 通过子进程、后台线程再造一个运行时宿主；进程内唯一宿主是硬约束。

**FR-101-013（启动顺序）**：宿主 MUST 在首屏内容加载完成之后才投递运行时；权限申请 MUST 在首屏内容加载之后（避免权限弹窗卡住启动屏）。

## 4 关键实体

| 实体 | 关键字段 | 不变量 |
|---|---|---|
| `RuntimeVerifier`（校验器） | 包名、版本、锁定哈希、校验结果 | 校验不过即硬失败；重复执行结果一致（幂等） |
| `LaunchPlan`（启动计划） | scriptPath、env、flags、logPath、投递时刻 | 每次启动一份；参数在投递前固定 |
| `ReadyMarker`（就绪标记） | `schema`、`url`、`port`、`pid`、`at` | `port > 0` 才有效；由写的方向维护（C3），读方只读不改 |
| `RuntimePhase`（阶段状态） | 六态枚举、进入时刻、原因 | 单向转移；终态不再回退 |
| `StageNotice`（阶段文案） | 序号、中文文案、结构化日志行 | 文案与日志一一对应 |
| `DiagnosticSnapshot`（诊断快照） | 状态、阶段、地址、错误、日志尾、崩溃记录 | 只读；不含密钥 |

## 5 验收场景

**AS-101-01 投递不等于就绪**（FR-101-001/002）
- Given 应用首次启动、运行时尚未监听
- When 启动调用返回
- Then 状态 MUST 仍为 `starting`，可渲染地址 MUST 为空/占位，界面 MUST 仍显示加载页

**AS-101-02 标记通道就绪**（FR-101-002）
- Given 运行时已写就绪标记且 `port > 0`
- When 宿主下一次轮询
- Then 状态 MUST 变为 `running`，快照 MUST 显示 `通道=marker` 与该端口；日志 MUST 出现一条命中记录

**AS-101-03 日志通道回退**（FR-101-002/003）
- Given 标记文件缺失，但本轮日志出现结构化就绪行
- When 轮询解析到该行
- Then 状态 MUST 变为 `running`，快照 MUST 显示 `通道=log` 与证据行；MUST NOT 采用上一轮的端口

**AS-101-04 旧标记作废**（FR-101-003）
- Given 上一次运行留下了旧标记（旧端口）
- When 本次投递开始
- Then 旧标记 MUST 在投递前被删除，日志 MUST 记录作废动作；若删除失败 MUST 记 warn 并保留「日志通道」退化路径

**AS-101-05 超时失败可见**（FR-101-002/009）
- Given 运行时未在超时上限内产生任何就绪证据
- When 轮询到期
- Then 状态 MUST 为 `failed`，最近错误 MUST 含超时值、尝试次数、标记路径与日志尾摘录

**AS-101-06 运行时篡改被拒**（FR-101-004）
- Given 运行时包内的 `libnode.so` 被替换成哈希不符的版本
- When 执行运行时校验（`verify-runtime.mjs`）
- Then MUST 以非零退出码失败，且构建流程 MUST NOT 继续

**AS-101-07 关停如实**（FR-101-011）
- Given 状态为 `running`
- When 收到终止前回调并发起关停
- Then MUST 记录关停原因与结果，界面/MUST 说明「真正停止只能靠进程退出」；MUST NOT 把状态改成 `stopped` 以外的成功态

## 6 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 投递调用 MUST NOT 阻塞界面线程（返回 ≤ 200 ms 量级，仅入队）；轮询 MUST 不产生可见卡顿；首启到可渲染地址耗时可测并落日志 |
| 可靠性 | 重复启动/重复关停 MUST 幂等；任一异常 MUST NOT 让界面停在无文案状态 |
| 可观测 | 状态转移、阶段、就绪证据、关停结果 MUST 各有一条结构化日志；日志尾可读 |
| 安全 | 口令与完整鉴权 URL MUST NOT 进入日志、快照、崩溃记录（宪法 S2/S3/S5） |
| 可测试 | 就绪解析、状态转移 MUST 是可离线单测的纯函数；真机判据 MUST 可用文件内容 + HTTP 断言 |
| 兼容 | 运行时版本/ABI MUST 与 `runtime.lock.json` 锁值一致；不一致 MUST 在构建期校验阶段暴露，而不是运行期 |

## 7 假设与约束

- 运行时契约以库文档为准，本模块只消费，不复述、不改写库的内部实现。
- 运行时监听端口由运行时侧分配；宿主 MUST 接受「端口未知 → 等标记」这一事实。
- 运行时每进程只能启动一次，崩溃不可恢复（宪法 C5）。
- 就绪标记由运行时侧脚本写入（102 交付），本模块只定义契约与读取判定（C3）。
- 单实例依赖应用清单的启动模式声明；系统层面的多实例行为 ⬜ 待真机确认（P0-H）。
